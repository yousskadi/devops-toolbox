# 2026-11-02 : Vault, lab 03 (auth methods)

Séance commencée le 2026-11-01 (étapes 1 à 4), terminée le 2026-11-02 (exercices).

## Ce que j'ai appris

- Une auth method sert à **prouver son identité** pour obtenir un token. Le login ne demande aucun token.
- **userpass** : pour les humains, mais en entreprise on préfère OIDC ou LDAP (MFA, départs gérés par l'annuaire). Sans `token_ttl`, le token dure 32 jours par défaut.
- Le réglage de l'utilisateur passe avant le défaut de la méthode d'authentification.
- **AppRole** : pour les machines. `role_id` est peu sensible, `secret_id` est le secret. Il n'y a pas de session : chaque login renvoie un nouveau token.
- `secret_id` = le ticket pour se connecter. Token = le badge obtenu ensuite. Les deux vivent indépendamment : détruire le `secret_id` ne coupe pas le token déjà délivré, il faut aussi le révoquer.
- `secret_id_num_uses=1` : un `secret_id` volé après usage ne sert plus, et s'il est utilisé en premier, le vrai job échoue et donne l'alerte.
- `token_ttl` est la durée de départ, `token_max_ttl` le plafond des renouvellements, compté depuis la création. `creation_ttl` ne change pas, `ttl` donne le temps restant.
- **Entité** : la fiche unique d'une personne. **Alias** : le lien avec son compte dans une méthode (`alice` sur `auth/userpass/`). Le **groupe** donne des droits à plusieurs entités.
- Les policies viennent de plusieurs endroits : `token_policies` sur le compte (inscrites dans le token), `identity_policies` via les groupes. C'est pour ça que `app-ro` n'apparaît pas sur l'entité d'alice (`policies []`).
- **Templated policy** : une seule policy donne à chacun son espace `users/<son-nom>/`.

| Ce que je modifie | Token existant |
|---|---|
| Le contenu d'une policy | Effet immédiat |
| Le groupe d'une personne | Effet immédiat |
| Entité `disabled=true` | Effet immédiat, et le token remarche à la réactivation |
| `token_policies` du compte | Reconnexion nécessaire |
| Mot de passe ou `token_bound_cidrs` | Le token reste valide, seules les nouvelles connexions sont bloquées |

Pour suspendre un utilisateur sans le supprimer : **désactiver son entité**. Si le compte est compromis : révoquer aussi ses tokens et changer le mot de passe.

## Erreurs rencontrées

- Copie de la commande d'alice pour créer bob : `token_ttl=1h` a suivi. Même chose pour `batch` avec `token_max_ttl=30m`. Quand je copie une commande, je relis toutes ses options.
- `VAULT_TOKEN=$DAVE` alors que le token était dans `$DAVE_TOKEN` : la variable vide a basculé sur root et `display_name` affichait `token`. Mon test ne prouvait rien.
- Confusion entre `secret_id` et token : le 2ᵉ login est refusé à cause du `secret_id` consommé, pas du token.
- `invalid role or secret ID` après une longue pause : le `secret_id` avait très probablement expiré (`secret_id_ttl=1h`).
